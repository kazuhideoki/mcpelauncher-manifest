# 2026-09-21 ワールド読み込み中のクラッシュ調査

## 現状と結論

**原因未特定。最初からJoy-Conを有効にした標準版で、ワールド読み込み中のSignal 11を観測した。**
同じワールドでも成功する試行があり、入力モードと成否は一対一には対応しない。
「ZL/ZRが原因」「重複イベントが原因」「競合が原因」のいずれも確定していない。

コントローラーをゲームに登録せずにワールドを開き、読み込み後に登録・再接続すると、
左右スティックとZL/ZRを操作できた。これは診断版での1回の回避成功であり、
根本修正・反復安定性・再接続対応の完了を意味しない。
標準プロファイルと配置済み実行ファイルには、この調査の変更を反映していない。

その後の合成入力による再現試験とポインタ追跡は
[STARTUP_REPLAY.md](STARTUP_REPLAY.md)に記録した。直近の実機比較では、変更していない
通常版・通常配置でも読み込みと操作が成功した。修正による解決確認ではなく、再現しなくなった状態。

## 調査対象

- Apple Silicon macOS、Minecraft `1.26.51.1 / 972605101 / arm64-v8a`。
- 標準プロファイル：`Joy-Con-Gamepad`、入力モード：`full`。
- 配置済みrelease：`d4c7ad05f27860f81754`。
- 配置済み本体SHA-256：`a6f93370bef1a00063a8d1cfe85998ebd49c286fa6b67fbe4f839db514b8c0ee`。
- game-window：`2a74fba1c84de033ad1047c128425dcdca8c089b`。
- 更新Mod：既存の`mcpelauncher-updates/1.26.45.1/arm64-v8a`。
- 同じ通常データ・同じワールドをユーザーが開いて比較した。

旧キーボード版削除後に問題が報告されたが、標準releaseの全チェックサムは一致した。
配置済み実行ファイルの逆アセンブルでも、GameActivityのMotionEvent.sourceが
`AINPUT_SOURCE_JOYSTICK`（`0x01000010`）であることを確認した。
削除による本体・依存ファイルの欠損や、以前のイベント種別修正の欠落は確認されていない。
削除との因果関係を完全に否定したものではない。

## 実施した比較

各成功はユーザーの実操作報告。回数が少なく、順序・接続状態・タイミングを完全に統制した試験ではない。

| 条件 | 結果 | 言える範囲 |
| --- | --- | --- |
| `connect`：登録のみ、入力なし | メニュー表示成功 | ワールド内操作の成功とは区別する |
| `buttons`：ボタンと十字キー | 同じワールドで操作成功 | この試行では再現せず |
| `left`：上記＋左スティック | 同じワールドで移動成功 | この試行では再現せず |
| `right`：上記＋右スティック | 同じワールドで視点操作も成功 | この試行では再現せず |
| `full`：上記＋ZL/ZR | 選択後、読み込み中にクラッシュ | ZL/ZRを押した瞬間ではない |
| 診断版：ZL側の軸だけ追加 | 最初は読み込み中にクラッシュ | ZRだけの問題とは言えない |
| 同じZL側診断版＋LLDB | 読み込み・スティック・ZL成功 | デバッガーによる影響は未確定 |
| 同じZL側診断版、LLDBなし再試験 | 同様に成功 | デバッガーなしでも成功する |
| 診断版：ZL/ZR両方 | 読み込み中にクラッシュ | トリガー値は左右とも0のまま |
| 変化のない軸イベントを抑制 | 同様にクラッシュ | この変更では解消せず。変更は撤回 |
| ゲームパッド登録自体を無効化 | 同じワールドの読み込み成功 | 登録ありの試験との対照。ただし反復未実施 |
| ワールド内に到達後、登録を有効化して再接続 | 左右スティック・ZL/ZR操作成功。ログにクラッシュなし | 現時点の回避成功 |

途中でJoy-Conの切断も記録された。また「ワールドを開いている」と想定した時点で
実際はワールド一覧だったため、その試行は読み込み後接続の成功として数えない。
最後はユーザーにワールド内の景色の表示を確認してから登録を有効化した。

## 実際の停止位置

従来のバックトレースに繰り返し現れた`libminecraftpe.so+0xaaf738c`は、
今回採取したコンテキストでは**呼び出し元への戻り先（LR）**だった。
ARM64の`SA_SIGINFO`ハンドラーで取得したfault PCは別の位置だった。

| 項目 | 採取値 |
| --- | --- |
| libminecraftpe.soのロードベース | `0x141e44000` |
| fault PC | `0x14c961b78`（ベースから`0xab1db78`） |
| 命令 | `ldr x23, [x0, #0x8]` |
| x0 | `0x275efbf8` |
| 不正アクセス先 | `0x275efc00`（x0＋8） |
| LR | `0x14c93b38c`（ベースから`0xaaf738c`） |

確定したのはゲーム内部の無効なポインター読み出しまで。
その値がいつ、どこで作られた／壊れたかは未特定。
32ビットへの切り詰め、解放後使用、初期化不足、競合などを、値の見た目だけで断定しない。
別の失敗ではワーカースレッドの`Json::Value`コピー処理など異なるスタックも出ている。

## 診断用変更と証拠の所在

[crash-context.patch](crash-context.patch)は、現在の固定ソースを隔離コピーしたものに適用した診断差分。
製品用の修正ではなく、通常の`setup.sh`には組み込んでいない。

- game-window：`full`のまま`MCPELAUNCHER_DIAGNOSTIC_TRIGGERS=left`または`right`で
  トリガー送信を片側だけに制限。未指定は両側。値が変わったときだけ値を記録。
- mcpelauncher-core：Apple ARM64のシグナルコンテキストからPC/LR/SP/FP、
  アクセス先、x0～x28を既存クラッシュ処理の前に記録。
- 効果のなかった軸イベント抑制は差分に含めない。

隔離ビルドは`/private/tmp/joycon-trigger-investigation/`にある。
`source/`が診断ソース、`build/`がビルド先、
`runtime/Contents/MacOS/mcpelauncher_client`が最後に使用した本体。
一時領域なので永続性は保証しない。ソース差分は上記パッチから確認できる。
再構築する場合は初期化済みcheckoutの隔離コピーにのみ適用し、
[build_probe.py](build_probe.py)のコピー・依存キャッシュ利用を参考に通常のCMakeビルドを行う。
古い`game-window-probe.patch`は重ねて適用しない。

非追跡の`.local/crash-investigation-20260921/`に、今回の生ログ12件のスナップショット、
LLDB採取スクリプト、要約、ログ・診断本体・パッチのSHA-256を保存した。
このディレクトリはローカル専用。認証関連情報等を含み得る生ログはコミット・共有しない。
調査時のログ元は`/private/tmp/joycon-*.log`。

## 確認できた回避手順と制限

診断版を`MCPELAUNCHER_JOYCON_MODE=full`で直接起動し、
`MCPELAUNCHER_JOYCON_PROBE_GATE`に**存在しないファイル**の絶対パスを指定する。
ゲームパッド登録を止めたまま、マウスでワールドを開く。
ワールド内に到達後、そのファイルを作成して登録を許可し、必要ならJoy-Conを再接続する。
今回のゲートは`/private/tmp/joycon-trigger-investigation/disabled-controller-gate`。
名前に反して、**存在すると有効、存在しないと無効**である。

これは標準ランチャーでそのまま使える手順ではない。
標準`launch_client.sh`はゲート環境変数を解除する。
既知の切断通知・押下解放の問題も残るため、ゲートの切替を恒久的な再接続対応と扱わない。
固定時間の待機だけで修正したことにしない。

## 次に調べること

目標は、メニューからコントローラーを使え、そのままワールドを開ける状態。

1. fault PC周辺の不正ポインターがどこで設定されたかを追跡する。
   必要に応じて呼び出し元での計測・ウォッチポイントを用い、寿命・初期化・競合の仮説を検証する。
2. 登録通知と入力イベントのどちらが関与するか、同じワールド・接続条件で比較する。
   成功1回を修正完了とせず、入力無効側も含めて反復する。
3. 原因が分かった段階で登録・通知・入力処理を修正する。
   読み込み後だけ動く回避策と、最初から使える恒久修正を区別する。
4. 最初から接続した起動、ワールド読み込み、左右スティック・ZL/ZR、終了・再起動を検証する。
   修正版の配置・PR・マージはまだ行っていない。
